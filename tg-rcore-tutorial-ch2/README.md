# 第二章：批处理系统与用户态系统调用（含动态图形渲染实战）

本章在第一章“最小执行环境”的基础上，实现了一个**批处理操作系统**（tg-rcore-tutorial-ch2）。它不仅能够依次加载并运行多个用户程序，支持了特权级切换和 Trap 陷入机制，本章节扩展版本中设计了面向系统调用的特权级图形绘制隔离，向用户态程序抛出 `SYS_DRAW` 系统调用完成“OS”七巧板的动态拼装演示。

通过本实验的学习与扩展实践，你将深刻理解：

- **特权级隔离与切换：** 理解 RISC-V 架构下为何需要 U-mode 限制用户程序，以及触发 Trap（如 `ecall`）来请求 S-mode 服务的全套特权级转换上下文保护流程。
- **系统调用的设计与调度：** 在已有 `write` 和 `exit` 基础上，学习如何设计与接入具有复杂业务能力（如显存操作）的系统调用（请求截获、入参抓取到结果反馈）。
- **静态 BATCH 与全生命周期管理：** 学习静态编译打包多程序的 `APP_ASM` 实现与装载策略；深入理解当程序间交替运行时，内核中长生命周期的全局资源（如此处的 GPU 设备和 Framebuffer 裸指针）的共享与多重借用。 

## 学习与实验流

- 学：细读 `rust_main` 里针对批执行环境与 Framebuffer 建立的预设绑定；研究 `handle_syscall` 处理器内是如何拆解各通用（a0-a7）寄存器来实现业务分发的机制。
- 教：分析内核主文件源码在切换应用过程中对指令缓存与 U-态栈管理操作；理解为何 Rust 需要特别运用 `core::ptr::addr_of_mut!` 等严格手段提取 `static mut` 来保证安全性。
- 用：基于已提供的批处理多任务挂载体系，体会用户程序如何通过多次 `ecall` 下发分步指令引发视觉暂停，完成通过**多程序与系统调用分发结合**实现的动态拼图演示。

## 项目核心文件结构指南

```
tg-rcore-tutorial-ch2/
├── .cargo/
│   └── config.toml     # 指定交叉编译目标以及挂载额外设备参数的 QEMU 执行脚本
├── cases.toml          # 定义将被打包进内核执行的用户程序队列项
├── build.rs            # 搜索、编译各细分用户态程序后拼接内联为 APP_ASM 并入内核的元构建脚本
├── Cargo.toml          # 包含底层 VirtIO 与 Alloc 模块引用的项目依赖管理表
├── src/
│   ├── main.rs         # 核心上下文分配及任务流控，含有全局 GPU 维持、陷入捕捉处理等框架主程序
│   ├── gpu.rs          # 硬件抽象及 DMA 层 （复用且升维）
│   └── tangram.rs      # 图形数据解算算法结构（供内核 Syscall 内联调用）
```

## 执行与展示方法

在 `tg-rcore-tutorial-ch2` 目录下执行编译并开启模拟：
```bash
cargo run
```
控制台（Console）将首先刷出图形和内存初始提示，并接着逐条播报用户库对应加载与终止的信息（`load appX`），与此同时 QEMU 图形窗口中展示每一小块拼凑出的 “OS” 图案，每次渲染即通过延迟环演示出肉眼可见的任务级挂转时间。

## 原理分析：软硬数据通道构建与多程序时分

**用户程序的安全沙盒与陷入响应**
应用不再具备全局总线能力，只能使用规定在 U 态的地址边界内，当应用程序下达一条 `ecall` 试图作画时，CPU 冻结应用，将其全部核心寄存器（User Stack/PC 流等）转存至 `LocalContext` 内，跳转回 S 态内核配置在控制状态寄存器 `stvec` 中的异常处理函数口。如果 a7 验证无误，才会调用安全态的硬件控制域解封逻辑代理工作。

**图形状态的长续共管模型**
图形界面在批处理的迭代更新时不能中断，这就决定了物理绘制控制器与其操作空间 `FB_PTR` 将跨越 `rust_main()` 和所有批次子任务流。必须借由在堆空间（由内核早期配置）维持活跃并利用粗暴的强制生命抑制脱离原栈范围控制。随后借助对底层裸指针的可控利用，才能使得每一个用户进程借由陷阱切回内核态操作时不互相推翻原有绘制历史并共享一致的终端显示目标。
